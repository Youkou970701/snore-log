# 需求确认单：呼噜记 · 夜间鼾声记录 App（暂名）

> 立项日期：2026-11-05
> 状态：**已拍板（2026-11-05），01 可开工**
> 缘起：用户想知道自己晚上打呼有多严重、有没有呼吸停顿。市面上有现成 App（SnoreLab 一类），但核心功能要付费。
> 分工同 sema-diary：**Claude 写 `docs/` 和 `fixtures/`（测试音频与标注）并验收，Codex 写代码（`core/` `ios/`）**。

## 要解决的问题

1. 睡着以后自己听不到，只能靠别人说「你打呼好响」——想要客观数字：打了多久、多响。
2. 担心的其实是**打呼中间突然没声了、过一会儿「咳」一声又接上**——这是呼吸暂停的典型声音模式，想知道一晚有几次、最长停多久。
3. 一晚 8 小时录音几百 MB，没人会全听。只要留下**值得听的几段**（最响的、疑似停顿的），其余听完就扔。

## 成功标准

1. 晚上点「睡觉」→ 锁屏放床头 → 早上闹钟响 → 点「起床」，**中间不用碰手机**，锁屏后录音不断。
2. 起床后 10 秒内出报告：打呼总时长/占比、最长连续打呼、最长不打呼间隔、疑似呼吸停顿次数和最长一次、打呼音量（约 dB）、整夜时间轴。
3. 每晚只留 **≤12 段** 2 分钟录音（自动挑最值得听的）。整夜音频只临时存到起床分析完（约 14 MB/小时），分析后立即删除；最终一晚占用 < 15 MB。
4. 闹钟可靠：锁屏、静音键打开、专注模式下都能响。
5. 全部在手机本地完成，**不联网、不上传**。

| 模块 | 内容 |
|---|---|
| 睡前 | 设闹钟（时间、铃声、贪睡开关）；可选「今晚因素」标签：喝酒 / 感冒鼻塞 / 很累 / 侧睡 / 吃了宵夜 / 戴了止鼾贴（多选，用于以后对比）；「延迟开始统计」0/10/20/30 分钟（默认 10，躺下刷手机那段不算） |

| 分析 | 每秒一帧：音量（约 dB）+ 是否打呼（苹果系统自带声音分类器，含 snoring 类）；合并成打呼段；检测疑似呼吸停顿（规则见下）。**跨 2 分钟分段边界的事件必须连续识别**，不能被切断 |
| 留存 | 每晚留 ≤12 段：疑似停顿段优先 → 最响的打呼段 → 最长连续打呼所在段；可点「收藏」永久保存，没收藏的 14 晚后自动删除 |
| 闹钟 | 到点响铃（优先用 iOS 26 系统闹钟能力 AlarmKit）；关闹钟后打开 App 一键「起床」结束录音；闹钟后 2 小时仍没点起床，自动结束（省电） |
| 报告 | 当晚报告 + 整夜时间轴（每分钟一格，颜色=打呼强度，红点=疑似停顿，灰=中断）+ 留存片段可直接播放；历史列表；同一因素标签的多晚均值对比（如「喝酒的晚上」vs「不喝酒」） |
| 设置 | 音量校准偏移（拿任意分贝计 App 对照一次，默认值见下）；留存天数；导出某晚报告（图片 + 片段音频，用于给医生听） |

## 这次不做（明确排除）

- **任何诊断**：不叫「睡眠呼吸暂停」「AHI」，不给严重程度定级、不推荐止鼾产品或治疗方案。
- 睡眠分期（深睡/浅睡/REM）、智能唤醒（浅睡时叫醒）——只靠麦克风做不准。
- 血氧、心率、接 Apple Watch / 健康 App（V2 再议）。
- 云同步、账号、多人、App Store 上架。
- 安卓（用户是 iPhone）。

## 关键规则（写死，Codex 不得自行改阈值；要改先提出来）

所有阈值标为「参数」，是产品初值不是医学标准，验收样本跑出问题再调。

| # | 名词 | 定义 |
|---|---|---|
| R1 | 帧 | 1 秒。每帧算：音量 dBFS → 约 dB（= dBFS + 校准偏移，默认偏移待真机标定，先用 90）；分类器 snoring 置信度 |
| R2 | 噪声底 | 最近 5 分钟帧音量的 10 分位数（滚动更新），用来适应空调、风扇 |
| R3 | 打呼帧 | snoring 置信度 ≥ 0.5 **且** 音量 ≥ 噪声底 + 6 dB |
| R4 | 打呼段 | 相邻打呼帧间隔 ≤ 8 秒的合并为一段（一次呼吸周期内吸气打呼、呼气安静是正常的）。「最长连续打呼」= 最长一段的时长 |
| R5 | 不打呼间隔 | 两个打呼段之间的时长。「最长不打呼间隔」只统计首次打呼到末次打呼之间 |
| R6 | 疑似呼吸停顿 | 同时满足：①前 60 秒内 ≥ 5 个打呼帧（正在打呼）；②随后连续 ≥ 10 秒安静（每帧音量 < 噪声底 + 3 dB，且无打呼/呼吸类声音）；③安静结束后 5 秒内出现「恢复声」：单帧音量 ≥ 前 60 秒打呼帧音量中位数 + 6 dB（憋醒的大喘/鼾爆），或重新打呼。只有①②没有③（比如翻身后不打了）**不算**；④安静时长 ≤ 90 秒（更长的是「不打了」，不是停顿；2026-11-05 验收样本 02/07/14 抓出漏了这条） |
| R7 | 停顿分档 | 10–20 秒 / 20–30 秒 / ≥30 秒，报告分别计数 |
| R8 | 音量统计 | 打呼音量报「中位数」和「P95」，**不报单帧最大值**（咳嗽、关门会冒尖）；最大值只在时间轴上可见 |
| R9 | 统计窗口 | 从「睡觉 + 延迟」到「起床」（或闹钟后自动结束）；中断时段从分母扣掉 |
| R10 | 留存 | 候选池在录音过程中滚动维护：池内最多 12 段 + 当前段 + 上一段（边界事件用）；新候选比池内最弱的强就替换并删掉弱的那个文件。事件跨边界时相邻两段合并成一条留存（计 1 条）。**候选只能指向提名时的当前段及前 2 段**（App 只留最近 3 段音频）；最长连续打呼取 run 结束处的末两段（2026-11-05 写 02 时定） |
| R11 | 打呼时段 | 同 R4 的合并方式，阈值 30 秒：相邻打呼帧起点相差 ≤30 秒归同一时段，中断切断。**报告里的「打呼时长」「最长连续打呼」「最长不打呼间隔」都用时段口径**；R4 的打呼秒数改称「鼾声发声时间」放次要位置（2026-11-07 真机第二晚：打呼秒数 69 分被用户当成「只录了 1 小时」，时段口径为 204 分/48%） |

## 安全与隐私红线

1. **唯一的主动健康提示**（固定文案，不推断原因）：当晚疑似停顿 ≥ 5 次/小时，或出现 ≥ 1 次 ≥ 30 秒的停顿时，报告顶部显示：
   「这晚检测到较多疑似呼吸停顿。手机录音可能误判，如果连续多晚都这样，或白天特别困、早上头痛，建议去医院睡眠科做睡眠监测。」
   其余地方只陈述数字。
2. 全部文案不出现「呼吸暂停综合征」「AHI」「重度」「确诊」类字样。
3. App 不申请网络权限、不带任何统计/崩溃上报 SDK；录音只在本机，导出由用户手动分享。
4. 录音会录到伴侣说话、梦话——留存片段列表首次使用时提示一次「片段只存在本机」。

## 决策与假设

| # | 决策 | 依据 |
|---|---|---|
| 1 | **形态 = 原生 iOS App（SwiftUI），不做 PWA** | iOS 网页锁屏/切后台麦克风就停，整夜录音只能靠原生 App 的后台音频模式；闹钟也只有原生能做可靠（AlarmKit） |
| 2 | 打呼识别 = 苹果 SoundAnalysis 框架内置分类器（自带 snoring 类，本地运行、免费、不用自己训练模型） | 先用它跑样本，准确率不够再加「呼吸周期 2–6 秒的节律」特征兜底 |
| 3 | 分析内核单独做成 Swift Package `SnoreCore`，输入 PCM，输出事件和报告；附命令行 `snore-analyze 某晚.wav` 出 JSON | **能在 Mac 上用整夜样本离线跑、自动测**，验收不靠真机睡觉；App 只是壳 |
| 4 | 录音格式：16 kHz 单声道；留存片段编码 AAC 32 kbps（2 分钟约 0.5 MB） | 打呼频段在 2 kHz 以下，16 kHz 足够 |
| 5 | 音频会话用 measurement 模式（关掉自动增益）；**代价是原始录音很小声（真机片段平均 −52～−59 dBFS），播放时必须放大**（只放大播放，不改存档） | 自动增益会把安静夜里的底噪拉高，音量数字就没法跨晚对比 |
| 6 | 音量只承诺「同一台手机、同一摆放位置下可对比」，不承诺准确 dB | 手机麦克风未校准；文案一律写「约 XX dB」 |
| 7 | 摆放建议：床头柜、离头 30–50 厘米、插着充电、麦克风朝床 | 首次使用引导页写明；电量 < 50% 且没插电时，点「睡觉」弹提醒 |
| 8 | 数据存储：每晚一条记录 + 每秒音量包络（8 小时约 2.9 万个数，几百 KB，全留，用于画时间轴）；音频只留候选池 | 包络便宜，音频贵 |

## 已知风险（Codex 开工前/02 期必须实测）

1. **后台跑分类器——已实测不可用（2026-11-06）**：SoundAnalysis 内置分类器锁屏后每次都报 `Error during analysis`（第一晚失败 692 次、打呼 0；前台/锁屏对照实验坐实）。改为夜里只录音+算 dB，起床后在前台统一分类（03a）。
2. **苹果分类器对远场鼾声的准确率未知**：它是为通用声音训练的，30–50 厘米外的轻鼾可能识别不出来。01 期用样本量化，不达标就加节律特征。
3. **风扇/空调/伴侣也打呼**：伴侣打呼分不出来是谁——V1 接受，引导页写明「同床有人打呼时结果包含对方」。
4. **闹钟铃声会被录进去**：闹钟响起后的帧不计入统计。
5. **AlarmKit**：用户是 iOS 27.0.1，可用；需在 02 期确认免费签名下能正常调度。
6. **免费签名 7 天过期**：过期后 App 打不开、闹钟不响。必须有到期提醒（见已拍板 2）。
